# Lab2 — Система управления турниром (фрагмент): Player / Match / Result

Проект — учебная лабораторная работа №2 по ООП на C++ (ручное управление памятью).
Реализован минимальный фрагмент предметной области турнира по настольным играм (шахматы/шашки):
- игроки (Player),
- матч между двумя игроками (Match),
- результат матча как часть матча (Result).

В коде демонстрируются:
- **композиция** (Match содержит Result и управляет его временем жизни),
- **агрегация** (Match ссылается на Player через указатели, не владея игроками),
- проверка одного правила предметной области,
- работа со стековыми и динамическими объектами (`new/delete`),
- работа со ссылками и указателями,
- динамические массивы объектов и массивы динамических объектов.

---

Класс Player
Ответственность: хранит данные об игроке и его статистику (победы/ничьи/поражения), которую обновляют матчи.
Поля (примерно):
 std::string m_name— имя игрока
 int m_wins, m_draws, m_losses— статистика
Методы:
 Конструкторы (например, Player(name)и/или Player())
 AddWin(), AddDraw(), AddLoss()— увеличивают соответствующие счётчики
 PrintBrief()— выводит краткую информацию об игроке
 ~Player()— деструктор (в проекте печатает сообщение для демонстрации времени жизни)
Правило предметной области, которое проверяет:
Правила (например, когда можно менять статистику) контролируются классом Match
при завершении матча.
(Если нужно обязательно указать правило для каждого класса, корректный вариант: “статистика игрока изменяется только через методы AddWin/AddDraw/AddLoss, прямого доступа к полям нет”.)
 
 Класс Result
Ответственность (1 предложение): хранит исход матча в формализованном виде (победа/поражение/ничья/нет результата).
Поля:
 Outcome m_outcome— перечисление исхода (None,P1Win,P2Win,Draw)

Методы:
 Set(Outcome)— установить исход
 Reset()— сбросить в None
 IsSet()— проверка установлен ли результат
 ~Result()— деструктор (печать)

Правило предметной области, которое проверяет:

“У матча может быть либо нет результата, либо ровно один результат из перечисления Outcome”. Технически это обеспечивается типом enum + контролируемой установкой через Set/Reset

 Класс Match
Ответственность: управляет жизненным циклом матча между двумя игроками: старт, завершение, фиксация результата и обновление статистики игроков.
Поля:
 Player* m_p1, Player* m_p2— участники матча (ссылки на уже существующих игроков)
 State m_state— состояние (Planned,InProgress,Finished)
 Result m_result— результат матча (часть матча)
Методы:
 Start()— переводит матч из Planned в InProgress
 Finish(Outcome)— завершает матч: ставит результат, переводит в Finished, обновляет статистику игроков
 PrintState()— печатает текущее состояние
 ~Match()— деструктор (печать)
Правило предметной области, которое проверяет:
“Нельзя завершить матч, который не идёт”.
То есть Finish() запрещён, если состояние не InProgress

Связи: композиция и агрегация (обоснование через время жизни)
Композиция: Match—Result
Что выбрано: Match содержит Result как часть себя (обычно полеResult m_result;)

Почему это композиция (через время жизни):
 Resultне существует сам по себе в модели — он имеет смысл только как часть конкретного матча.
 Если уничтожить “целое” (Match), то “часть” (Result) уничтожится автоматически вместе с ним (это видно по выводу: после [dtor] Match destroyed сразу идёт [dtor] Result destroyed).

Что произойдёт при уничтожении целого: удалили матч → результат исчез вместе с матчем.

Агрегация: Match—Player

Что выбрано: Match хранит указатели/ссылки на игроков (Player*), но не владеет ими.
Почему это агрегация (через время жизни):
 Игроки могут существовать до матча и после матча, участвовать в нескольких матчах.
 Уничтожение “целого” (Match)не должноуничтожать игроков.


Что произойдёт при уничтожении целого:
удалили матч → игроки остаются жить; можно после удаления матча вызвать у игрока метод и распечатать статистику

## Структура проекта

- `include/`
  - `player.hpp` — объявление класса Player
  - `match.hpp` — объявление класса Match
  - `result.hpp` — объявление класса Result
- `src/`
  - `player.cpp` — реализация методов Player
  - `match.cpp` — реализация методов Match
  - `result.cpp` — реализация методов Result
